# 다음 AI 인수인계: 회사·직무 기여의 증거로 마무리

2026-10-14. 사용자는 기존 대화 작업과 Cowork 361a916을 함께 활용해 S-OIL 수급 현업 담당자에게 회사 방향·직무 이해·기여 가능성을 보여주려 한다. 이 문서가 기존 확장 계획보다 우선한다. 기능을 늘리는 것이 최종 목적이 아니다.

## 먼저 읽기

AGENTS.md → 이 폴더의 01-company-role-message.md → 02-decision-evidence.md → validation-summary.json 순으로 읽는다. 세부 근거는 기존 docs/02·06·07·08, cowork/2026-10-14-supply-decision/01~04 및 VALIDATION.md를 따른다.

공식 업무: 공장최적화·원료 구매, 용선·통관, 수급·재고·판구매 관리. 구현 범위: 생산계획을 주어진 조건으로 둔 발주 전 추가 조달 비교. 두 범위를 혼동하지 않는다. 샤힌 통합 운영은 이해의 배경이지 구현 성과가 아니다.

## 1500자에서의 역할

포스코 약1000자는 사용자가 직접 작성한다. 그 경험에서 현실의 목적·제약을 확인하고 판단 기준을 수정한 행동, 실제 팀 활동을 입증한다. AI가 포스코 본문을 대신 쓰거나 강약점·성과를 추가하지 않는다.

나머지 약500자의 메시지: 생산계획에 필요한 원료의 시점·물량·가격·거래조건을 정리하고, 실행 가능한 대안과 판단을 바꾸는 근거를 설명할 수 있다.

권장 배치: 앞 경험의 방법을 수급에 적용한 연결50자, 회사·산업 배경80자, 공개자료와 가정 내부정보의 구조화110자, 추가 조달 대안과 조건별 판단150자, 배움·직무 기여110자. 실제 문장에 따라 조정하되 산업 뉴스가 행동·판단의 증거를 밀어내지 않게 한다.

500자에서는 샤힌 방향과 운송 불확실성을 짧게 연결하고, 같은 구매량·기말재고에서 필요한 조기물량·추가비용을 비교한 행동, 최소구매량 반례를 우선한다. 원유가격 수치, 카고 수, 테스트 개수, 프로그램명은 필수가 아니다.

## 사용자가 먼저 설명할 세 질문

1. 하루 지연에는 C80, 이틀 지연에는 B가 선택된 이유는 무엇인가? 80/160kbbl의 필요물량과 추가비용을 직접 계산한다.
2. B가 소량도 공급하면 왜 결론이 바뀌는가? E와 B의 최소물량·가격·한도가 별개임을 설명한다.
3. S-OIL에 실제 적용하려면 무엇이 더 필요한가? 생산·원료 적합성, 실제 견적·공급 확약, 입항·통관·품질 일정, 저장·인수조건을 구분한다.

검토 전에는 '프로젝트로 확인한 조건'으로 표현한다. 검토 후에만 본인의 배움과 수행으로 서술한다. AI 보조 구현을 처음부터 혼자 개발한 실적으로 바꾸지 않는다. 완성 자기소개서와 개인 메모는 공개 저장소가 아닌 별도 전달물로 둔다.

## 출처와 숫자 처리

직무·과거 인터뷰는 이번 HTML 본문 재확인. Bahri 계약, EIA 10월 자료는 공식 검색 수록 본문 확인. 샤힌 공식 블로그는 검색 요약과 사용자 자료를 확인했으며 개별 발표·IR PDF 재확인은 실패했다. Cowork의 PDF 텍스트 확인 기록을 삭제하지도, 이미지 확인 완료로 승격하지도 않는다.

1Q26·2Q26 IR 이미지 대조 전 카고 수·Dubai 값·가동률을 새 필수 수치로 채택하지 않는다. 83%를 회사 전체 원유 자급률로 쓰지 않는다. 전체 유가 시계열 수집·실측 경제성 검증을 했다고 쓰지 않는다.

## 유지·변경·기각

실제 B 소량구매가 가능하면 기존 C 우위 가정을 수정한다. 분할 고정비·저장 제약·품질 미승인이 확인되면 후보를 다시 걸러낸다. 모든 후보가 막히면 가능안 없음과 추가 협의사항을 제시한다. 실제 원료가 동등하지 않으면 현재 모형의 실제 구매 추천 용도를 기각한다.

고객 인수·생산 변경을 계산하려면 별도 범위로 먼저 설계한다. 현재 500자를 위해 P2·P3·대시보드·에이전트 기능을 추가할 필요는 없다. 모든 신규 기능은 어떤 주장에 증거를 더하는지 먼저 설명해야 한다.
