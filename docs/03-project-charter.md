# 프로젝트 목적과 범위

## 1. 먼저 결정한 역량

보여줄 것은 ‘정유 모델을 코딩할 수 있다’가 아니다.

**시장 정보와 현장 조건을 같은 기준으로 정리하고, 실행할 수 없는 대안을 걸러낸 뒤 경제성의 차이와 추가 확인사항을 설명하는 능력**을 보여준다.

산업과 회사 분석에서 구매·운송·생산·판매를 연결할 필요를 확인했고, 공식 직무소개와 과거 인터뷰가 이런 연결 업무를 설명한다.[R01, R02; 출처는 ../sources/registry.md] 그래서 도구를 선택하기 전에 비교할 질문과 성공 기준부터 정했다.

## 2. 중심 질문

원료의 가격상 이점이 운임, 도착 시점, 재고와 출하 제약 때문에 사라질 때, 무엇을 확인하고 어떤 계획을 다시 비교해야 하는가?

첫 구현은 ‘더 싼 원료가 더 좋은 계획’이라는 단순 기준을 일별 물량수지와 저장 한도로 다시 점검한다. 수급 전체를 재현하지 않고 판단 기준을 설명할 만큼만 구현한다.

## 3. 세 가지 사례와 구현 상태

| 사례 | 비교할 문제 | 근거와 입력 | 상태 |
|---|---|---|---|
| C1 도착원가와 입고·재고 | 낮은 도착원가, 빠른 대체 조달, 일부 브리지 물량 중 어떤 후보가 물량·일정 제약을 충족하는가 | 직무·수송 관계는 공개자료, 가격·물량·일정은 전부 가상 | 표준 라이브러리 산술 예제와 10개 테스트 구현 |
| C2 외부 판매와 내부 투입 | 중간유분을 팔지 않고 후속 공정에 넣을 때 포기하는 가치와 추가로 얻는 가치를 같은 기준으로 비교할 수 있는가 | 통합 운영 사례는 공개자료, 실제 수율·가동제약·변동비는 미확보 | 설계만 작성, 회사 손익 계산하지 않음 |
| C3 신규 제품 생산과 출하 준비 | 생산 준비, 고객 인수, 배관·탱크 여유의 시점이 어긋날 때 어떤 정보를 요청하고 어떤 계획을 보류해야 하는가 | 회사의 샤힌 준비·배관 계약, 실제 램프업·고객 인수율·계약 물량은 미확보 | 설계만 작성, 실제 생산·수출 개시로 표현하지 않음 |

### C2의 계산 설계

외부 판매 순회수액 = 판매대금 − 추가 판매·운송 비용.

내부 투입의 추가 기여 = 후속 제품의 추가 순회수액 − 추가 전환비용 − 필요한 외부 투입비용 − 외부 판매를 포기한 순회수액.

모든 값을 같은 투입량·기간·통화로 맞춘 뒤 비교한다. 이미 외부 판매 포기액을 차감했다면 내부 이전가격을 같은 의미로 한 번 더 비용에 더하지 않는다. 품질·수율·공동 생산물·공정 여유·에너지·정비·판매 약정을 확인하지 않고 비교 결과를 실행안으로 올리지 않는다. 실제 공장에서는 병목의 기회비용이 추가될 수 있으나 공개자료만으로 그림자가격을 추정하지 않는다.

### C3의 관찰 설계

기계적 완공 → 예비 시운전·시운전 → 규격 적합 제품 → 고객 인수 → 반복적인 정상 생산·출하를 구분한다. 고객 인수 지연은 생산 지연과 같지 않고, 배관 계약은 실제 가용 용량과 같지 않다. 각 단계의 확인일, 근거, 필요한 승인과 미확인을 기록한다. 상업가동 일정이 확인되면 단계 정의와 사례 전제를 갱신한다.

## 4. 첫 예제의 비교 원칙

구매량 500kbbl, 기초 240kbbl, 일일 사용 80kbbl, 7일, 기말 180kbbl을 모든 후보에서 동일하게 유지한다. 값은 모두 가상이다. 최소재고 80kbbl과 저장 한도 600kbbl도 학습용 가정이다.

입고는 해당일 사용 전에 일어나며 입고 직후 용량과 일말 최소재고를 모두 검사한다. 낮은 비용을 얻기 위해 사용량을 몰래 줄이거나 기말재고를 더 소진하지 않는다. 물리 제약을 위반한 계획은 비용 비교의 추천 대상에서 제외한다. 비교 가능한 대안이 없으면 ‘없음’을 반환한다.

세 가지 미리 정한 후보 중 최저비용 후보를 찾는 것이지 가능한 모든 계획의 최적해를 구하는 LP가 아니다. 모든 가격·일정은 시나리오 입력이며 예측값이 아니다. 코드는 발주나 현장 시스템에 연결되지 않는다.

## 5. 근거와 가정의 분리

공개자료는 왜 이 문제를 검토하는지 설명한다. 가상 데이터는 계산과 판단 기준을 점검한다. 가상 데이터가 S-OIL의 손익·재고·계약 노출을 설명하는 근거가 될 수 없다.

사실에는 원문·기준일·확인 수준을 붙이고, 해석에는 전달경로와 반대 설명을 적는다. 미확인 값은 0으로 채우지 않는다. 회사의 계획·설계 목표는 실현된 효과와 나누어 기록한다.

## 6. 검증 순서와 중단 조건

1. 원문 점검: 원문이 말한 내용과 분석자의 해석을 분리한다.
2. 전달경로 점검: 가격과 이익 사이에 운임·도착·수율·판매·계약 조건이 빠지지 않았는지 본다.
3. 현실 점검: 실제 물량·고객 인수·가동 데이터가 없으면 회사 실행안으로 넘어가지 않는다.
4. 반대 설명과 갱신: 순위를 바꾸는 입력과 가정을 공개한다.

실제 원료 호환성이나 운송 조건을 알 수 없으면 ‘검토 후보’만 제시한다. 비교 기준이 다르면 계산을 중단한다. 검증된 회사 데이터가 없다면 회사 절감액·최적 구매량·가동률은 출력하지 않는다.

## 7. AI의 역할과 확장 조건

현재 예제는 AI가 없어도 재현 가능한 산술 코드다. AI는 원문 정리, 후보 비교표 초안, 코드와 테스트 작성의 보조에 사용한다. 원문 채택·전제 선택·실행 가능성 판단의 책임을 자동화하지 않는다.

향후 자료량이 늘면 검색·표준화·반복 점검을 자동화할 수 있다. 다만 자료 검색 속도의 향상이 곧 의사결정 품질의 향상이라는 뜻은 아니다. 재사용 가능한 도메인 구조가 다음 분석을 돕는 피드백이 있는지, 검증 병목·자료 갱신·권한·비용이 이를 제한하는지를 측정한다. RAG·그래프·에이전트는 이 필요가 입증된 후 선택한다.

## 8. 다음 작업의 완료 조건

회사 자료 갱신: IR·ESG 본문, 샤힌 가동 단계, 모집공고 범위를 확인해야 한다. C2 확장: 공개 수율로 충분한 범위인지 검토하고 부족하면 회사명이 없는 가상 사례로 남긴다. C3 확장: 계약·공정 준비·고객 인수 증거를 분리한 일정표를 만든다. 성과 측정: 동일 과제를 기존 방식과 구조화 방식으로 실제 수행한 뒤 시간·누락을 기록한다.

현재 구현되지 않은 C2/C3나 측정하지 않은 개선율을 이력서·자기소개서의 완료 성과로 쓰지 않는다.
