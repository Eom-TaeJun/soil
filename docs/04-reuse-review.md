# 기존 GS칼텍스 작업물에서 무엇을 재사용하는가

검토 기준: 2026-10-14.

대상: https://github.com/Eom-TaeJun/refinery-value-chain-decision-lab

확인한 기준 커밋: b4fef3b2a987b84ff906c2688533615b7b569ea8.

## 확인 범위

저장소 트리와 README.md, docs/project-charter.md, scripts/validate_network.py를 읽었다. 전체 문서와 127KB 규모의 그래프 JSON을 전수 검토한 것은 아니다. README의 설명과 실제 검증 스크립트를 대조해 재사용 방향을 정했다.

기존 README는 52개 노드, 64개 엣지, 4개 회사 프로필과 8개 조건부 경로를 가진 초기 구조를 설명한다. 실제 회사의 수치 보정이나 최적화 계산은 수행하지 않았다고 명시한다. 검증 스크립트는 연결, 출처, 경로, 미확인 값과 가상 예제의 산술 일관성을 검사한다. 이것이 인과관계나 회사 손익을 입증하는 것은 아니다.

## 가져오는 것

가격·수요 변화가 어떤 원료·공정·제품·판구매 판단으로 이어지는지 추적하는 방법, 물리적 연결과 경제적 해석의 분리, 출처 ID와 가정의 관리, 조건부 주장에 반대 근거를 붙이는 방식, 미확인 값을 측정값처럼 보이지 않게 검사하는 원칙을 참고한다.

## 가져오지 않는 것

GS칼텍스의 AVCO 조직명, 직무별 배치 설명, DAX 표현, 원유 조달 국가·등급 수, 공장 용량, 회사별 노출 비중과 그래프 연결을 S-OIL에 복사하지 않는다. 같은 정유산업이더라도 조달·생산·판매 관계와 지원 문항이 다르기 때문이다.

기존 문서는 GS칼텍스 DX/AX 문항을 위한 작업물 성격이 강하다. 이번 S-OIL 문항은 몰입 경험과 사람 간 협업, 강약점과 배움까지 요구한다. 따라서 새로운 개인 프로젝트의 기술 기능만 늘려서는 문항 전체의 근거가 되지 않는다.

## 이번에 바꾸는 중심

큰 관계망을 먼저 확장하기보다 S-OIL 공식 수급 설명에서 확인한 구매·수송·재고의 연결을 작은 비교 사례로 보여준다. 실행 가능성이 다른 대안을 가격만으로 비교하는 오류를 먼저 검증한다. 다른 제품과 공정으로 확장할 때에도 회사 데이터와 가상 가정을 분리한다.

원본 코드와 데이터 파일은 복제하지 않았다. 이번 examples/arrival_inventory.py는 위 검토 원칙에 맞춰 별도로 작성한 제한된 산술 예제다.
