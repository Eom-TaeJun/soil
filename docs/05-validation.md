# 검증 기록

실행일: 2026-10-14.

## 실행한 검사

로컬 Python 환경에서 아래 명령을 실행했다.

```bash
python examples/arrival_inventory.py --test
python examples/arrival_inventory.py
```

10개 단위 테스트 통과: 기본 비용 비교, 입고 지연 시 재고 하한, 운임 변화에 따른 순위, 일별·기말 물량수지, 브리지 물량의 재고, 입고 직후 용량, 실행 가능한 후보가 없는 경우, 기간 밖 입고, 총구매량 불일치, 음수·NaN·기말재고 불일치 입력 거절.

세 시나리오 각각 세 후보를 계산했다. 기본은 A, 지연과 운임 상승은 B가 조건을 충족하는 최저비용 후보였다. 모든 경우의 구매량과 기말재고를 동일하게 두었다. 자세한 숫자와 가정은 [예제 설명](../examples/README.md)을 본다.

## 이 검사로 입증하지 못한 것

경제적 인과관계의 실증, S-OIL 실제 재고·손익·설비 조건, 실제 원유의 동등성, 선박·통관·탱크의 사용 가능성, 회사의 계약 승인권한, 예측 정확도, 기존 업무 대비 개선율을 입증하지 않는다.

10개 통과는 정의한 단위 테스트의 결과이지 모든 오류가 없다는 보증이 아니다. 외부 현업자의 검토나 회사 내부 데이터 검증을 받지 않았다. GitHub Actions 자동 실행도 이 단계에서 설정하지 않았다.

## 원문과 재현성

첨부 링크 모음의 49개 항목을 출처 목록의 출발점으로 삼았지만 모든 원문을 전수 재열람하지 않았다. 본문 확인, 검색 발췌, 기존 기록만 있는 자료를 sources/registry.md에서 분리한다. 특히 최근 IR·ESG PDF와 2026년 10월 IEA·EIA 본문을 확보하지 못한 상태에서 실제 수치를 만들어 넣지 않았다.

예제는 외부 API·데이터 파일·API 키가 없어도 실행된다. Python 3.10 이상에서 표준 라이브러리만 사용한다. 결과 JSON은 실행 시 생성되며 원문 자료를 대체하지 않는다.

## 다음 검증

회사 수율과 품질을 사용하는 단계에서는 단일 원료 가정을 폐기한다. 일중 출하·입고 순서가 중요한 경우 시간 단위를 세분화한다. 용선·취소·하역·통관 조건이 확인되면 비용과 제약으로 분리한다. 새로운 코드와 측정 성과가 추가될 때 구현 상태와 검증 기록을 함께 갱신한다.
