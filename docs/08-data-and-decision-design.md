# 외부자료와 가정 내부정보를 연결하는 데이터 설계

목적: 500자에서 주장할 산업 이해·데이터 구조화·판단 근거를 재현 가능한 작업물로 만든다. 공개자료로 내부시스템을 복제하지 않는다.

## 1. 선택한 질문

**가격이 유리한 원료 조달안도 필요한 때 사용할 수 없다면 계획을 어떻게 다시 비교할 것인가?**

주 사례 P1은 도착원가와 사용 가능 재고다. P2 내부 유분 배분·기회비용과 P3 샤힌 생산·고객 인수·출하 연계는 회사 맞춤 해석과 후속 설계로 남긴다. 기능을 늘려 500자의 핵심을 흐리지 않는다.

## 2. 지표의 우선순위와 자료 경계

| 지표 | 쓰는 이유 | 현재 자료 상태·통제 |
|---|---|---|
| 원유 기준가격, 원료별 차등 | 원료 조달조건의 공통·개별 요인 구분 | Brent 9월 월평균만 공개 과거 기준. Dubai·실제 OSP·거래가격 미확보 |
| 노선별 운임·보험료 | 구매가격 우위가 도착원가에서도 남는지 | 계약별 실측 견적 미확보. 가상값. 보험 포함 여부로 중복 합산 방지 |
| 도착·하역·통관·품질확인일 | 도착한 물량과 쓸 수 있는 물량 구분 | 화물별 가상 일정. 현재 예제는 일 시작에 하역 완료를 단순 가정 |
| 사용 가능 재고·운영상 하한·저장용량 | 총량이 맞아도 중간 공백·입고 순간 초과 탐지 | 내부에 존재한다고 가정하는 정보유형. 실제 회사 수치 아님 |
| 제품별 순판매가치·스프레드 | 유가와 정제·제품 수익성을 분리 | 실제 지역·규격·인도조건별 가격 미확보. 거시 경유 지표로 대체 계산 금지 |
| 투입 적합성·운전 범위·정비 | 샤힌 원료 유연성을 무제약 대체와 구별 | 가상 승인상태만 P1에 반영. 회사 수율·LP·공정별 제한 미확보 |
| 고객 인수·출하·계약 상태 | 생산 준비가 실제 공급·판매인지 판단 | P3 설계. 실제 회사 약정·고객별 데이터 미확보 |
| 비축 방출·생산정책·항로 사건 | 재검토할 시점과 가설을 찾음 | 외부 관찰·발표. 실제 화물 도착이나 운임 상승폭으로 자동 변환하지 않음 |

환율·운전자금은 후속 민감도 축이다. 현재 비교는 USD로 고정해 환율 가정을 섞지 않는다. 달러 조달비용 상승을 원화 순손익 악화로 자동 확정하지 않는다. 기업 매출·판매대금·헤지·금융조건도 필요하다.

## 3. 객체·관계와 행 단위

- Source/Metric: `source_id`, URL, 발행일, 확인일, 관측기간, 지역·유종, 값, 단위, 관측/전망/정책/계약, 확인 수준. 같은 이름이라도 지역·기간·기준이 다르면 합치지 않는다.
- Event: `event_id`, 발생·발표·시행일, 영향받는 항로·제품·설비, 근거, 반대 경로, 추가 확인사항. 기사 제목에서 원인·영향 수치를 만들어내지 않는다.
- Parcel: `parcel_id`, 원료·계약·항로, 물량, 가격조건, 운임·보험 포함 범위, 도착·통관·품질확인 시점, 적합성 상태. 회사 내부표의 존재·명칭은 가정이다.
- Inventory: `material_id × location_id × date × status` 한 행. 도착 물량, 품질대기, 사용 가능, 예약 물량을 구분. 현재 예제는 단일 가상 원료·저장위치로 축소했다.
- Plan/Allocation: `plan_id × date × material_id × use_or_destination`, 요구물량, 허용 운전범위, 내부 투입·외부 판매, 고객 인수조건. P2/P3에서 구현할 구조다.
- Decision/Review: `scenario_id × plan_id`, 위반 제약, 비교 비용, 근거 ID, 누락·상충 정보, 질문을 받을 기능, 재검토 조건. 추천과 실제 승인·실행은 다른 상태다.

관계: 사건 → 항로/원료/제품 → 화물 → 사용 가능일 → 일별 수지 → 후보의 가능 여부 → 경제성 비교 → 확인·승인 요청.

추가 관계: 내부 유분 → 내부 투입 또는 외부 판매 → 포기한 외부 순판매가치 → 후속 공정 산출 → 고객 인수·출하. 배럴과 톤은 성상·밀도 없이 환산하지 않는다.

## 4. 계산 규칙

도착원가 예제 = 공통 과거 기준가격 + 가상 차등 + 가상 운임 + 운임에 미포함인 가상 보험료. 실물 구매에는 가격결정 기간·인도조건·손실·세금·금융조건 등이 더 필요하다. 현재 결과를 실제 회사의 landed cost로 쓰지 않는다.

사용 가능일 = max(가상 도착·하역완료일, 통관일, 품질확인일). 각 절차가 선행돼도 물량이 도착하기 전에는 쓸 수 없다.

사용 가능 기말재고 = 전일 사용 가능 재고 + 당일 사용 가능 전환량 - 계획 사용량.
저장량은 사용 가능 물량과 품질·통관 대기량을 모두 포함해 입고 직후 용량을 검사한다. 음수 계획수지는 불가능성 진단이지 실제 음수 재고가 아니다.

후보의 총구매량·사용량·기간·기말재고·동등 원료 가정을 맞춘다. 실제로 서로 다른 원유라면 품질·수율·공정 제약이 확인되기 전 비교하지 않는다. 미확인은 0이나 적합으로 바꾸지 않는다.

P2 설계에서 내부 투입 기회비용은 포기한 외부 순판매가치다. 내부 이전가격을 함께 더해 중복 비용화하지 않는다. 증분 공헌가치가 양수여도 설비·고객 제약을 위반하면 선택할 수 없다.

## 5. 실제 외부자료와 가상조건의 연결 방식

[data/public_context.json](../data/public_context.json)의 M01은 EIA가 발표한 2026년 9월 Brent 월평균 114 USD/bbl이다. 현재 시세나 회사 구매가격이 아닌 과거 공통 기준으로만 사용한다. M02의 4분기 전망 105 USD/bbl은 별도 보관하고 관측치 자리를 대신할 수 없게 검사한다.

공통 기준가격이 모든 후보에 동일하게 적용되고 물량도 같으므로 기준가격 자체는 후보 순위를 바꾸지 않는다. 이번 예제의 순위 차이는 가상 차등·운임과 운영 제약에서 나온다. '공개 유가로 최적 구매안을 찾았다'는 표현은 금지한다.

외부 사건은 시나리오를 검토할 이유를 제공한다. 지연 2일, 운임 변화폭, 품질대기 2일은 관측 사건에서 추정한 계수가 아니라 가정이다. 회사 항로·비중·가격계약이 확보되기 전 뉴스로 실제 비용·지연일을 보정하지 않는다.

## 6. 구현·검증의 범위

P1 확장 구현: 7일 물량수지, 3개 후보, 7개 시나리오, 도착과 사용 가능 구분, 품질대기 저장용량, 적합성 미확인 보류, 동률·가능안 없음, 출처·관측/전망 구분. [검증 결과](10-readiness-validation.md) 참조.

P2/P3 미구현: 내부 유분별 실제 수율·증분가치, 후속 생산·판매 수지와 고객 인수 제약. 외부 시장가격·항차 실측과 연결한 보정, 실제 사용자 시간·오류 개선, 전체 공장 최적해, 실행 승인도 없다.

AI는 자료 후보·스키마·코드·누락 점검을 보조한다. 사용자는 자료 채택과 해석·검증 결과를 확인한다. 실제 발주·용선·운전 변경을 실행하지 않는다. 자동화와 정보 축적의 편익은 측정 전에는 가설이며, 전문 검토가 병목이면 기술 추가만으로 해결됐다고 보지 않는다.
