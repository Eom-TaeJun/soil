이 문서와 AGENTS.md의 2026-10-14 2차 지시가 기존의 포괄적 확장 계획보다 우선한다. 저장소의 기존 파일을 읽지 않고 덮어쓰지 않는다.

## 목적과 금지 범위

전체 1500자 중 사용자가 작성하는 포스코 약 1000자는 건드리지 않는다. 이 저장소는 나머지 약 500자에서 산업·S-OIL 이해와 수급 판단을 위한 데이터 구조화 역량을 증명하는 용도다. 공개 저장소에는 미제출 자기소개서, 비공개 경험 원문, 개인 강약점·계정정보를 넣지 않는다.

고정 메시지: 시장 변화를 실제 사용 가능한 원료·재고와 생산·판매 조건에 연결해, 실행 가능한 대안을 숫자로 설명하고 추가 확인사항을 정리한다. 특정 최적안·절감률은 고정하지 않는다.

회사·직무와 최근 사건을 근거/해석/미확인으로 정리했다. 공개 과거 기준가격과 합성 운영조건을 분리한 P1, 7개 시나리오와 14개 테스트를 실행했다. 500자 메시지·증거 배치와 주장 가능한 경계를 정했다. 이 내용은 사용자 실무성과가 아니다.

## 다음 우선작업

P0: 가능한 접근으로 2026년 2분기 IR, 2025 ESG, 10월 14일 IEA OMR 원문을 재확인한다. PDF 표는 페이지 이미지까지 확인하고 기준기간·발행일을 남긴다. 접근 실패가 계속되면 실패를 유지하고 구자료·검색 요약으로 최신 수치를 만들어내지 않는다.

P1: 사용자와 사례를 검토해 저가안 유지·변경·보류·가능안 없음 각각의 이유를 직접 설명할 수 있게 한다. 출처의 시점 차이와 예측치를 관측치로 바꾸지 않는 원칙도 설명해야 한다. 제출 문장은 사용자가 실제 확인·수행한 범위에서만 쓴다.

P2는 필요할 때만: 샤힌 맥락을 더 입증해야 하면 내부 유분의 외부 판매 대 내부 투입 기회비용을 별도 가상 사례로 만든다. 같은 투입량·산출 기준에서 수율·적합성·추가비용·고객 인수를 정의하고 반대 결과도 테스트한다. 기존 P1 원료 1종 가정을 실제 원유 대체로 확대하지 않는다.

P3는 선택: 고객 인수나 출하가 늦을 때 생산 준비와 실제 공급의 차이를 보이는 상태표. 안전·품질·상업가동을 스스로 승인하지 않는다. 회사가 실제 지연 중이라고 단정하지 않는다.

자동화·대시보드·다중 에이전트는 현재 필수 산출물이 아니다. 새 기능이 500자의 메시지에 어떤 증거를 추가하는지 한 문장으로 설명되지 않으면 구현하지 않는다.

## 수정 후 검사

```bash
python examples/readiness_case.py --test
python examples/readiness_case.py
python examples/arrival_inventory.py --test
```

공개 값은 source_id·발행일·기간·단위·지역·종류·확인수준을 가진다. 모든 가상 운영값은 합성 표식을 유지한다. 기준가격이 공통일 때 순위가 유지되는 반례, 적합성 미확인 보류, 입고 순간 용량, 같은 구매·사용·기말재고, 가능안 없음이 유지돼야 한다.

기준일·수치·가정을 바꾸면 결과와 문서를 함께 갱신한다. 원격 HEAD를 확인하고 동시 변경을 보존한다. 커밋 생성과 브랜치 반영을 구분하고 실제 반영된 SHA를 다시 읽는다. 테스트 실행 없이 통과라고 쓰지 않는다.

## 중단·축소 기준

내부 필수조건 없이 실제 원료 순위를 주장해야 한다면 회사 최적화가 아닌 정보 요청표로 범위를 줄인다. 현실성 확인이 부족하면 모델을 복잡하게 만들지 말고 미확인 목록을 개선한다. 산업 뉴스 소개가 길어져 프로젝트의 판단 근거가 사라지면 사건을 한 개로 줄인다.
